# Naviamp 2.10.0 manual acceptance

Status: **Windows feature approvals and positive Mac smart-playlist/Autoplay feedback recorded;
remaining interactive and cross-platform acceptance stays open. Release publication is on hold**.

The [October 21 Mac checkpoint](macos-2.10.0-2026-10-21.md) records owner feedback, visible
Library/artist/changelog checks, profile retention, 494 locally passing automated cases, and the
remaining manual checks blocked by the Mac computer-use connection. These are separate evidence
levels; the automated results do not check off the complete manual matrix below.

The candidate is v2.10.0/build 60, compared with public v2.9.0. Use the latest commit of
`fix/286-restore-release-version` reviewed in [PR #287](https://github.com/goosepod/naviamp/pull/287)
and [PR #288](https://github.com/goosepod/naviamp/pull/288). It integrates accepted main through
the all-platform mTLS work (#298), readable summaries (#299 / #300), artist playlists (#302 / #303),
stationary Library search with explicit refresh (#304 / #305), and consistent server matches
across Library tabs (#306 / #307), configurable artist Top Tracks (#308 / #309), organized artist
settings (#310 / #311), and artist playlist/appearance album layouts (#312 / #313). The PRs and
[acceptance issue #280](https://github.com/goosepod/naviamp/issues/280) record the exact candidate
commit, automated check results and artifact links. Record the actual tested commit and artifact
hash below; an earlier candidate's acceptance does not establish acceptance of this tree.

No tag creation or modification, GitHub Release (including drafts), announcement, milestone closure
or Forgejo mirror is part of this preparation. The existing failed tags remain untouched. Performance
work (#203, #220, #241) and the separate native accessibility follow-ups remain deferred.

## Smart playlists

The owner rejected the summary and library-scoped preview feedback on 2026-10-19, then reported
smart playlists working fine on the Mac candidate on 2026-10-21. This positive feedback does not
establish that every advanced case below was exercised.
Follow-ups [#314](https://github.com/goosepod/naviamp/issues/314),
[#316](https://github.com/goosepod/naviamp/issues/316) and
[#318](https://github.com/goosepod/naviamp/issues/318) remain linked to their detailed retest steps.
Use the [summary retest steps](314-smart-playlist-summary-preview.md),
[sample-sync retest steps](316-smart-playlist-sync-progress.md) and
[library names, compact samples and popup retest steps](318-smart-playlist-editor-results.md).

- [ ] Start with a valid condition and an invalid second condition, both at the top level and inside
      a group. Save/preview must block with the invalid row identified. Correct or remove it and retry.
- [ ] Check an impossible date, leap day, reversed range and decimal rating. Entered invalid text
      remains editable. Save/reopen preserves decimal values, sort priority and Unlimited/track/% limits.
- [ ] Open an unsupported definition: inspect its original JSON without an editable save path.
- [ ] Pick regular and smart playlists by name; search, distinguish duplicate names and verify saved
      references survive reopen. A missing/inaccessible reference retains its ID. Self-reference is blocked.
- [ ] Read the summary for nested ALL/ANY, exclusions, playlist membership, quoted text, favorite/non-favorite tracks,
      numeric/date ranges, relative days, missing/present predicates and plain-language sort direction.
      Names should replace resolved IDs; unavailable references retain an identifiable fallback. A false
      missing/present flag reverses the displayed predicate. JSON syntax must not leak into ordinary values.
- [ ] A favorites-only playlist reads as favorite tracks, without “Favorite is yes” or a redundant
      ALL wrapper. Verify named library restrictions, exclusions, sort precedence and the track limit.
- [ ] For a preview blocked by missing library membership, read the explanation, choose **Sync library**
      and verify matching examples appear when the server supplies the metadata. A server that does not
      supply it must retain the explanation, without claiming zero matches or ignoring the library filter.
- [ ] Collapse/reopen Options and Advanced; values and the saved definition remain unchanged.
- [ ] Sync metadata from the builder. Samples are labeled as local, potentially incomplete and separate
      from final server ordering. Invalid rules cannot silently disappear from preview. Change conditions
      quickly and confirm an old sample result cannot replace the latest one.
- [ ] Check a narrow window, touch/keyboard selection and at least one long-label translation. Confirm
      a visible caret, sensible focus, Escape/cancel behavior and readable errors. Check the summary after
      playlist lookup completes or a previously unavailable reference becomes resolvable.

## Certificate-protected connections

Use disposable certificates and media, or a deliberately selected test account. Do not install test
authorities into the OS trust store. Import files independently on each tested device; settings sync
does not transfer private certificate files or identity passwords.

- [ ] Import a password-protected PKCS12 identity and the test server's private CA. Connect, browse
      and load artwork. Remove/move the original selected files, restart, and confirm the saved private
      copies still work.
- [ ] With persistent audio caching/prefetch disabled, start an uncached long track before it has fully
      downloaded. Pause, seek beyond buffered audio, resume and stop. Repeat after app restart.
- [ ] Switch source/track during startup and stop a slow stream. Old authenticated reads must end;
      failures must not be reported as natural completion or advance the queue as a success.
- [ ] Try a wrong PKCS12 password, missing/untrusted client identity, untrusted server CA and hostname
      mismatch. Each must fail clearly without insecure fallback. Test a private-CA-only server separately.
- [ ] Where available, repeat with a representative compressed format and transcoding, in addition to
      the automated WAV fixture. Document buffered-seeking limits for servers without finite byte ranges
      or provider time offsets; do not report unrestricted seeking for those configurations.

Automated production-adapter evidence and reproduction are in
[all-platform mTLS verification](mtls-all-platforms-2026-10-15.md),
[Windows mTLS verification](mtls-windows-2026-10-15.md) and [testing.md](../testing.md).
Those earlier results are supporting evidence, not a substitute for this candidate's manual acceptance.
