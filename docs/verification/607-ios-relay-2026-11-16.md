# iOS wiring and shared relay cleanup, November 16, 2026

Issue: https://github.com/goosepod/naviamp/issues/607. Branch: `codex/607-dlna-upnp`.
Baseline: `cd0d5b009`. This increment is unreviewed work in progress on the draft branch.

## Scope and ownership

Core supplies UDP socket execution through Ktor, HTTP relay framing and lifetime, opaque-token
encoding, discovery policy, capability gating, queue/session reconciliation and foreground-only
relay policy. The native hosts supply interface facts, operating-system randomness, the HTTP engine
and unavoidable host lifecycle effects. No second iOS queue, receiver controller or provider client
is introduced.

Android's Cast and UPnP HTTP adapters now delegate to `NaviampKtorMediaHttpServerEffect`. The adapter
shrinks from 188 to 40 lines and retains only ConnectivityManager-based LAN address selection and
validation of an explicitly selected interface. The previous native request parser, HTTP response
framing and unbounded per-client coroutine loop are removed. Shared tests exercise HEAD/ranges,
chunked responses, malformed requests, cancellation, stop and restart. Desktop's existing adapter
translates the JDK HttpServer API and does not contain the removed hand-written socket parser.

The shared UDP executor preserves numeric packet-source and selected-interface identity, rejects
oversized and invalid UTF-8 packets, and releases sockets/selectors on stop or startup failure.
Loopback testing initially exposed Ktor's reverse-resolved `hostname` property returning `localhost`;
using raw address bytes fixes the identity check without weakening description-origin pinning.
SSDP bytes, registry limits, scan generation and retry policy remain in the existing common owners.
Passive multicast NOTIFY reception and network rebinding are still separate unfinished work.

The iOS host injects the dedicated Darwin control transport and shared relay/discovery executors.
Its NSURLSession has no credential storage, cookie storage or response cache; provider authentication
and TLS configuration stay on the existing provider byte-source path. SecRandomCopyBytes fills the
shared 32-byte token encoder. getifaddrs/getnameinfo expose usable IPv4 interface facts without sending
packets. Normal app builds still report `NaviampUpnpMulticastAvailable=NO`; both the picker and direct
Core renderer selection reject an unavailable multicast capability.

SwiftUI scene phase forwards background/foreground facts to Core. A temporary inactive state, such
as a permission sheet, is not mapped to background. UIKit grants a short background execution lease
for cleanup, ended on completion or expiration. Core invalidates pending selections, leaves local
playback paused, attempts bounded receiver cleanup and revokes the relay. Failed Stop responses do
not escape background/host shutdown cleanup or start the local speaker. Returning to the foreground
does not reconnect or resume playback. The iOS resource owner now waits for shared shutdown before
closing its native HTTP engine, playback integration and database.

## Native boundary audit

- `apps/android/src/main/kotlin/app/naviamp/android/AndroidNaviampCastHttpServerEffect.kt`:
  ConnectivityManager/NetworkCapabilities and Inet4Address expose and validate native LAN addresses;
  all HTTP framing and listener lifetime delegate to Core.
- `platforms/ios/src/iosMain/kotlin/app/naviamp/ios/platform/IosNaviampUpnpEffects.kt`:
  Darwin NSURLSession initialization/lifetime, Security SecRandomCopyBytes, POSIX interface APIs and
  NSBundle build metadata are concrete Apple boundaries; receiver/protocol decisions stay common.
- `apps/ios/src/iosMain/kotlin/app/naviamp/ios/NaviampIosApplication.kt`:
  the iOS composition root supplies those effects and orders shared shutdown before releasing native
  resources; its scene callback delegates the event directly to Core.
- `apps/ios/iosApp/NaviampRootView.swift`:
  SwiftUI scenePhase and UIApplication background-task identifiers supply native lifecycle facts and
  execution-lease lifetime, with no receiver or queue policy.
- `platforms/ios/build.gradle.kts`: dependency metadata adds the Darwin HTTP engine.

No Desktop production file changes. No new user-facing copy, setting, persistence schema or minimum
OS version is introduced.

## Limits and remaining acceptance

The owner explicitly prohibited use of the Onn TV until they are present to check it. This increment
must not send discovery probes, playback commands or any other test traffic to that receiver.
Local test fixtures use loopback addresses and generated data. No new audible playback, Onn, WiiM,
bit-perfect output or physical gapless result is claimed. No push or CI run was performed for
this local increment.

Apple Multicast Networking entitlement approval for the exact App ID remains unconfirmed. No Apple
account capability, provisioning profile or signing setup has been changed. The existing opt-in
entitlement/signing procedure in the implementation plan still applies; a build flag is not proof
of approval or signed entitlements. Simulator success cannot validate real-device local-network
privacy, multicast entitlement enforcement, background suspension or execution-budget expiration.
See [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)
and [UIKit background execution](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).

Real-device iOS permission allow/deny, discovery, background/foreground, sleep and network-loss
checks remain open. Android's new shared relay also needs native runtime qualification. Existing
network/VPN, GENA callback/renewal, broader control/format and actual WiiM lossless/gapless gates
remain open; keep PR #608 draft and issue #607 open.
