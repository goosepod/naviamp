## Configuration and observed results

Windows JVM test host on the same Wi-Fi LAN as an Onn Android TV running AirPin STD 5.7.1
(package version code 571). Receiver name: `APTV_223`. No screen pairing code is needed for UPnP.
Provider fixture: generated eight-second sine tone, original FLAC, stereo, 44,100 Hz, 16-bit,
132,248 encoded bytes. The test provider rejects requests other than `StreamQuality.Original`.

| Check | Result | Evidence and limits |
| --- | --- | --- |
| Native multicast discovery | Passed | Real `JvmNaviampUpnpDiscoveryEffect` sends M-SEARCH; the common discovery owner resolves the response and description. No manual target injection into the controller. |
| AirPin SSDP interoperability | Passed after fix | AirPin adds trailing CRLF lines; common parsing now accepts them. A shared regression assertion covers this form. |
| Capability negotiation | Passed | AirPin advertises `audio/flac` and `audio/x-flac`; the shared media plan chooses original FLAC. |
| Shared queue and relay | Passed | The canonical live queue/controller hands off to `NaviampCoreUpnpSession`; the receiver actually requests provider bytes through the scoped Core relay and reports PLAYING. |
| Audible FLAC | Passed | The owner confirmed hearing the short tones from two live probes. This establishes audible playback, not bit-perfect physical output or high-resolution support. |
| Pause/resume/stop | Passed | Commands go through the shared remote controller; the test independently queries AirPin for PAUSED_PLAYBACK, PLAYING and STOPPED. |
| Seek | Acknowledgment only; position not confirmed | A seek to two seconds was tested. AirPin continued to report zero in GetPositionInfo before and immediately after resume; a strict position assertion timed out. Do not count successful SOAP acknowledgment as a verified audible seek. |
| Gapless | Unsupported by this receiver's advertised standard interface | AVTransport omits `SetNextAVTransportURI`; Core reports `supportsNext=false`. No physical gapless transition was attempted or claimed. `Next` alone is insufficient evidence. |
| WiiM | Untested | There is no WiiM hardware in this test. |

The live fixture listener uses JDK HttpServer behind the shared listener contract, rather than
launching the Desktop UI or using the Android application as sender. The native JVM UDP adapter,
common HTTP client, protocol, queue, media endpoint and provider-byte source are real. Android TV
is the **receiver**, so this is not evidence that Android sender permissions/lifecycle work.

## Reproduction

`NaviampAirPinLiveProbeTest` is opt-in and skipped in ordinary CI. Set these environment variables
only in the shell running the probe:

- `NAVIAMP_AIRPIN_LOCATION`: the current receiver description URL.
- `NAVIAMP_AIRPIN_LOCAL`: the receiver-reachable host IPv4 address.
- `NAVIAMP_AIRPIN_FLAC`: absolute path to the generated FLAC fixture.

Generate the fixture with FFmpeg:

```text
ffmpeg -f lavfi -i sine=frequency=440:sample_rate=44100:duration=8 -ac 2 -c:a flac -y a.flac
```

Run (quote the `-P` argument in PowerShell):

```text
.\gradlew.bat --console=plain --max-workers=2 '-Pkotlin.native.enableKlibsCrossCompilation=false' :core:presentation:jvmTest --tests '*NaviampAirPinLiveProbeTest' --rerun
```

`--rerun` prevents Gradle from reusing an earlier test result when only environment variables
change. The probe discovers `APTV_223`, checks that it matches the supplied location, controls it,
and sends Stop during cleanup. It must be run only with permission to use that receiver.
It prints sanitized results, without media tokens, pairing codes or reusable provider credentials.
