## Initial verification

The first local pass validated 1,677 shared/provider JVM tests, architecture, migration checks,
Android debug unit tests, and Android debug native packaging. Desktop platform tests passed 39/40.
The generated WAV decode/EQ test failed again in isolation. Windows DX8 PARAMEQ rejects the 31 Hz
and 62 Hz bands and restricts the upper center frequency based on sample rate. See the
[native API documentation](https://www.un4seen.com/doc/bass/BASS_DX8_PARAMEQ.html).

CMake is installed at the Android SDK's `cmake/3.22.1/bin/cmake.exe`; this shell needs `CMAKE_EXE`
set explicitly. The initial PATH failure is environmental, separate from the native test failure.

Local evidence: `build/release-readiness-check.log`, `build/release-readiness-retry.log`, and
`build/release-readiness-native-repro.log`. Coverage and Android release tests were not completed
by the interrupted full gate. GitHub does not yet contain the reviewed feature commit, so its CI
cannot establish readiness. Native iOS checks require a macOS runner.

## Platform diff accountability

- `platforms/android/src/main/kotlin/app/naviamp/android/playback/AndroidBassJni.kt`: reads the native
  stream frequency and marshals the shared equalizer plan into the JNI parameter array.
- `platforms/desktop/src/desktopMain/kotlin/app/naviamp/desktop/playback/bass/DesktopBassJniBinding.kt`:
  loads Windows DLLs through `System.load`, reads native stream frequency, and marshals the shared plan.
- `platforms/ios/src/iosMain/kotlin/app/naviamp/ios/playback/IosBassPlayback.kt`: translates the shared
  plan into `BASS_DX8_PARAMEQ` cinterop fields and manages native effect handles; the duplicate
  frequency list and gain policy were removed.
- `native/bass-jni/src/naviamp_bass_jni.cpp`: resolves Windows BASS FX symbols and translates shared
  parameter triples into BFX/DX8 structs, managing the native effect handle lifetime. Partial failures
  now remove all effects created by that call.

Build metadata additionally requires `bass_fx.dll` in Windows native inputs and packaged resources.
Vendor copyright/provenance files are retained alongside the DLL; input validation treats only
native-library extensions as libraries.

Shared domain tests and Android/JVM/iOS arm64 domain compilation passed before host wiring
(`build/stabilization-common-final.log`). The iOS platform adapter itself cannot compile on this
Windows host: Gradle skips that task. Its final compile/native validation is an explicit Tuesday gate.
