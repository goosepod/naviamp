# Naviamp documentation

This directory contains maintained user, contributor, architecture, protocol, dependency, and
provenance documentation. GitHub is the durable record for planned and completed work:

- [Issues](https://github.com/goosepod/naviamp/issues) track features, fixes, acceptance work, and
  future ideas.
- [Pull requests](https://github.com/goosepod/naviamp/pulls) retain implementation and review
  history.
- [Releases](https://github.com/goosepod/naviamp/releases) contain versioned release notes.
- [Discussions](https://github.com/goosepod/naviamp/discussions) contain announcements and community
  proposals.

Completed implementation plans, stabilization logs, audit checkpoints, and duplicated release
notes are intentionally left in Git history rather than retained as current documentation.

## Maintained documents

- [`architecture/0001-shared-runtime-thin-hosts.md`](architecture/0001-shared-runtime-thin-hosts.md)
  defines the shared-runtime and thin-host architecture.
- [`development-workflow.md`](development-workflow.md) defines repository, branch, review, release,
  and mirror procedures.
- [`testing.md`](testing.md) documents the verification matrix.
- [`ios-sideloading.md`](ios-sideloading.md) documents installation of the unsigned iOS preview.
- [`opensubsonic-api-audit.md`](opensubsonic-api-audit.md) records OpenSubsonic protocol decisions
  and source evidence.
- [`bass-native-dependency-inventory.md`](bass-native-dependency-inventory.md) and
  [`bass-addon-usage-audit.md`](bass-addon-usage-audit.md) record native audio dependencies and
  their supported uses.
- [`genre-ontology-dataset-research.md`](genre-ontology-dataset-research.md) and
  [`genre-ontology-import-audit.md`](genre-ontology-import-audit.md) preserve dataset provenance and
  generated-import evidence.
- [`samples/lyrics/`](samples/lyrics/) contains representative word-timed lyric fixtures.
