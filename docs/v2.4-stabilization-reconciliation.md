`release/v2.4.0` diverged from `feature/library-discovery-playlists` at `c6b3c648`.
Its September 6 commits `cfd89703` and `5f5e145c` were not ancestors of the published
v2.4.0 tag (`57383b00`) or main's final acceptance record (`50c8a935`). Main's September 8
release work continued from the same common ancestor without these changes. The repository
contains no recorded decision to drop them.

This merge preserves both commits in main's ancestry and restores their common equalizer plan,
Windows BASS FX adapter and binary, native processing regressions, settings/migration tests,
and missing Spanish discovery resources. Main's newer published release notes, version/build
numbers, and release acceptance remain authoritative. The equalizer and translation fixes are
listed under Unreleased; the historical stabilization checklist and announcement draft are
explicitly marked as records of the unshipped candidate. Existing release tags are not moved.

The Android TV branch will receive this main merge rather than an independent cherry-pick,
so both branches share the recovered history.

## Platform production diff

All frequency selection, gain normalization, bandwidth, flat-band, and Nyquist policy is owned
by `core/domain`'s `EqualizerPlan.kt`. The changed host files only connect this common plan to
native effects:

- `platforms/android/src/main/kotlin/app/naviamp/android/playback/AndroidBassJni.kt` reads the
  stream's native sample rate and passes common parameter triples through JNI.
- `platforms/desktop/src/desktopMain/kotlin/app/naviamp/desktop/playback/bass/DesktopBassJniBinding.kt`
  loads the bundled Windows DLL through the JVM and passes common parameters through JNI.
- `platforms/ios/src/iosMain/kotlin/app/naviamp/ios/playback/IosBassPlayback.kt` maps the common
  plan to BASS cinterop structures and manages native effect handles.

`native/bass-jni/src/naviamp_bass_jni.cpp` translates the same plan to Windows BFX or other
platforms' DX8 ABIs and cleans up partial native effect creation. Build scripts, upstream native
assets, and tests exercise or package those boundaries. The Windows DLL's SHA-256 matches its
checked-in provenance (`a6e1847eef52d882b4137af514d834c2e220daceb417c821d1e502fb7a34c84a`).
