# v2.12.1 hotfix readiness

The candidate is based on the published v2.12.0 tree at
`b61abc3b1` (tag `v2.12.0`), following the hotfix procedure in
[development workflow](../development-workflow.md#hotfixes). Scope is one shared Jellyfin
provider fix and release metadata. The candidate is v2.12.1 / build 66.
[Jellyfin 12 stream authentication #730](https://github.com/goosepod/naviamp/issues/730)

## Problem

Jellyfin 12.0 disables legacy authorization by default (`EnableLegacyAuthorization`), including
on upgraded servers. Naviamp's REST requests already used the current
`Authorization: MediaBrowser … Token="…"` header, but `JellyfinProvider.streamUrl` still
attached the token as the legacy `api_key` query parameter. Players fetch stream URLs directly,
without Naviamp's headers, so Jellyfin 12 treated those requests as unauthenticated and logged
"Invalid token."

The defect is in shared provider code, so it affects every platform. It surfaced on Android
first because the reporter's playback used transcoded streams.

## Live server evidence

Probed a Jellyfin **12.4.0** test server (the reporter's version) with a token from
`/Users/AuthenticateByName`:

| Request | `api_key=` | `ApiKey=` | No token |
| --- | --- | --- | --- |
| `GET /Users/Me` | 401 | 200 | — |
| `GET /Audio/{id}/universal` (transcoded stream) | 401 | 200 | 401 |
| `GET /Audio/{id}/stream?static=true` (direct stream) | 206 | 206 | 206 |
| `GET /Users/Me` with the `Authorization` header | — | — | 200 |

Jellyfin 12 ignores `api_key` entirely. Direct static streams kept working only because that
endpoint accepts anonymous requests; every transcoded stream failed.

## Fix

`streamUrl` now sends `ApiKey` instead of `api_key`. `ApiKey` is the non-deprecated query form
that earlier Jellyfin releases also accept, so no server-version branching is needed. The REST,
artwork, download, and Cast proxy paths already authenticate with the `Authorization` header and
are unchanged. Playback diagnostics already redact every query value, and the stream-detail
redaction matches `apikey` case-insensitively.

Shared tests in `JellyfinProviderTest` assert `ApiKey` and the absence of `api_key` for both
direct and transcoded stream URLs.

## Platform diff

No Android, Desktop, or iOS production source changed. The iOS and tvOS project files change
only `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION`.
