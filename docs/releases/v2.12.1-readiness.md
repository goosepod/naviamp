[development workflow](../development-workflow.md#hotfixes). Scope is two shared Jellyfin
fixes and release metadata. The candidate is v2.12.1 / build 66.
[Jellyfin authentication #730](https://github.com/goosepod/naviamp/issues/730) ·
[Hotfix PR #731](https://github.com/goosepod/naviamp/pull/731)

## Problem 1: second sign-in signs out the first device

Every installation on a platform sent the same Jellyfin `DeviceId` (`naviamp-android`,
`naviamp-desktop`, `naviamp-ios`, `naviamp-tvos`). Jellyfin revokes a user's earlier tokens
for a `DeviceId` whenever that user signs in with it. Signing in on an Android TV therefore
revoked the phone's token. The phone's next saved-session restore received 401 from
`/Users/Me`, and signing in again on the phone revoked the TV in turn. This matches the
reported sequence. Review on #731 identified it.

Verified on the Jellyfin 12.4.0 test server:

| Step | Result |
| --- | --- |
| Sign in with `DeviceId` X (token A), then again with X (token B) | A → 401, B → 200 |
| Sign in with a different `DeviceId` Y (token C) | B and C → 200 |
| Use token C with a mismatched `DeviceId` header | 200 |
| Sign in with that mismatched `DeviceId` | C still 200 |

A token keeps working when it is sent with a different `DeviceId`, and the server does not
re-associate it. Moving existing installations to a new identifier therefore signs nobody out.

## Problem 2: transcoded streams rejected by Jellyfin 12

Jellyfin 12.0 disables legacy authorization by default (`EnableLegacyAuthorization`), including
on upgraded servers. Naviamp's REST requests already used the current
`Authorization: MediaBrowser … Token="…"` header, but `JellyfinProvider.streamUrl` still
attached the token as the legacy `api_key` query parameter. Players fetch stream URLs directly,
without Naviamp's headers, so Jellyfin 12 treated those requests as unauthenticated and logged
"Invalid token."

Probed the same server with a token from `/Users/AuthenticateByName`:

| Request | `api_key=` | `ApiKey=` | No token |
| --- | --- | --- | --- |
| `GET /Users/Me` | 401 | 200 | — |
| `GET /Audio/{id}/universal` (transcoded stream) | 401 | 200 | 401 |
| `GET /Audio/{id}/stream?static=true` (direct stream) | 206 | 206 | 206 |
| `GET /Users/Me` with the `Authorization` header | — | — | 200 |

Jellyfin 12 ignores `api_key` entirely. Direct static streams kept working only because that
endpoint accepts anonymous requests; every transcoded stream failed.

Both defects are in shared code or shared wiring, so they affect every platform.

## Fixes

- **Per-installation device identifier.** `naviampProviderDeviceId` in `core:presentation`
  creates one random identifier per installation (`<platform prefix>-<random hex>`) on first
  use. It is stored under a device-local key, validated before it reaches a header, and never
  exported, imported, or synced. Settings export is built from typed settings rather than raw
  keys, so the key cannot leak into it. iOS and tvOS get it through the shared
  `NaviampStoredApplication`; Android and Desktop pass it into their provider session wiring.
- **Stream authentication.** `streamUrl` now sends `ApiKey` instead of `api_key`. `ApiKey` is
  the non-deprecated query form that earlier Jellyfin releases also accept, so no
  server-version branching is needed. The REST, artwork, download, and Cast proxy paths
  already authenticate with the `Authorization` header and are unchanged. Playback diagnostics
  already redact every query value, and the stream-detail redaction matches `apikey`
  case-insensitively.
- **Recovery for already-revoked tokens.** No code change was needed. Opening a saved
  connection restores using only its token. Editing that connection and entering the password
  re-authenticates and updates the same saved row instead of adding a duplicate. A shared test
  now covers this path.

## Platform diff

| File | Native boundary |
| --- | --- |
| `platforms/android/.../settings/AndroidDeviceIdentityValueStore.kt` (new) | Android Auto Backup and device transfer copy SharedPreferences per file, so the identifier needs its own file excluded from backup. |
| `apps/android/src/main/res/xml/backup_rules.xml`, `data_extraction_rules.xml` | Android backup manifest rules exclude that file. |
| `platforms/android/.../connection/AndroidCoreProviderSessions.kt` | Replaces the `naviamp-android` constant with the Core-provided identifier (parameter only). |
| `apps/android/.../AndroidNaviampCoreCatalog.kt` | Host composition passes the Android identity store to the Core function. |
| `platforms/desktop/.../connection/DesktopCoreProviderSessionPort.kt` | Replaces the `naviamp-desktop` constant with the Core-provided identifier (parameter only). |
| `apps/desktop/.../app/DesktopComposition.kt` | Host composition passes the Desktop settings store to the Core function. |
| `apps/ios/.../NaviampIosApplication.kt`, `apps/tvos/.../NaviampTvosApplication.kt` | Renamed argument only: the platform value is now the prefix for the Core-generated identifier. |

The iOS and tvOS project files change only `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION`.
On iOS and tvOS, a device backup restores the settings and the database together, so a
restored device inherits a consistent identity and token rather than a mismatched one.
