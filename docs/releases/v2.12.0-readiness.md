# v2.12.0 release readiness

Issue: https://github.com/goosepod/naviamp/issues/635
Milestone: https://github.com/goosepod/naviamp/milestone/12

## Frozen scope

Base: public v2.11.3. `release/2.12.0` was cut from accepted `main` commit
`f16264a2f` (Save the iOS compiler cache again by skipping booted-simulator tests, #634).

Selected scope: Apple TV beta (#590), CarPlay beta (#43), Android Auto UX and capability
cleanup (#350), Aurral as an optional companion to a primary music server (#587), and internal
build/CI work (#592, #633).

Release metadata on `chore/635-release-preparation`: VERSION `v2.12.0`, VERSION_CODE `65`
(v2.11.3 shipped as 64). The release branch still lacks the v2.11.3 changelog section and
hotfix metadata (#600 is open); both must be carried into this preparation PR.

## Open release blockers

1. **Aurral 3 support (#587) — fixed on `fix/587-aurral-v3`, pending PR and port.** Aurral
   3.0.1 reports app API version 2 and dropped the v1 feature names, so the v1-only client
   disabled every Aurral surface. Owner decision (2026-11-20): support Aurral 3.x only and
   drop Aurral 2.x. The shared client now requires API version 2 and maps the v2 contract
   (Library IDs from `libraryAlbumId`/`album.id` with boolean `managed`, `/api/library`,
   `/api/library/albums/:id/status`, `accessPlaylists`, v2 monitoring bodies, no
   `triggerSearch`, no Lidarr manager). Aurral 3's session-only release cover route is read
   through the cover list so the session never follows its external redirect. Verified:
   provider Aurral unit suites (all pass), `AurralLiveTest` 15/15 against the owner's live
   3.0.1 server, and on the Pixel 6a: companion Home card, recommendations (500),
   artist details, sample playback, release covers, recent requests and Trending. Request,
   monitoring and feedback writes were not exercised against the live server. Upgrade note
   for release text: Aurral 2.x servers are no longer supported. README updated.
2. **In-app changelog — updated on `chore/635-release-preparation`.** CHANGELOG.md has the
   v2.12.0 section and the missing v2.11.3 section. The shared About changelog lists the
   v2.12.0 public changes against v2.11.3 (Aurral companion, CarPlay beta, Apple TV beta
   from source, Android Auto, settings-import fixes, Aurral 3 requirement). The changelog,
   About and TV regression tests pass and the rendered About page was checked. The
   settings-import and Aurral 3 entries assume #640 and #636 are merged and ported before
   the tag; remove them if either is deferred. No community contributions are in scope, so
   no Thanks section.
3. **Linux release zip loses executable permissions — fixed in #638 (issue #637), pending
   merge and port.** Verified in WSL: the fixed zip stores all 6 executables as `0755` and
   launches; without the fix the new archive check fails the build. macOS zip not run
   locally (same task and check). Original finding: `bin/Naviamp`, `jspawnhelper` and
   the bundled `.so` files are not executable after unzipping, so the zip does not launch.
   Gradle 9.9.1 (from #610) normalizes archive permissions and `Zip.packageDesktopApp` in
   `apps/desktop/build.gradle.kts` sets none. `.deb`, `.rpm` and the app image are
   unaffected. The macOS zip must be checked for the same defect.
4. **Settings import breaks the active connection — fixed in #640 (issue #639), pending
   merge and port.** Connect → Import → enter password → Connect failed with "A connection
   with this provider… already exists" and left no active source, because the imported
   profile was opened as a new connection. It now reconnects the imported profile.
5. **Settings import reset volume to 100 — fixed in #640.** Export intentionally omits
   device-local playback settings; import now keeps the receiving device's volume, output
   device, debug logging and mobile-download values. Both fixes are covered by common
   tests; a hands-on re-check in the packaged app is still needed.

Observations:

  still reported PLAYING for a finished single-track queue while the audio stream was

## Hands-on acceptance: Windows

Packaged `:apps:desktop:packageReleaseDistributable` (windows-x64), run from an isolated
profile. Full report and screenshots are kept outside the repository by the test session.

Pass: first launch and About (v2.12.0 Build 65), Home and artwork shapes, browse and
search, playback controls and gapless, settings persistence across restart, idle CPU
0.3–0.8% and playing 1.7–4.0% of a core, minimize/restore/close/reopen and taskbar icon.

Fail or bugs:
- Aurral (blocker 1) and changelog (blocker 2).
- Settings import leaves no active server: Connect after import fails with "A connection
  with this provider… already exists". Reconnect from Settings → Source recovers it.
- Settings export/import saved and restored volume 100 instead of the live 34.
- Full player is clipped at 1280×800 and 1024×720 (volume slider half hidden; collapse,
  cast, lyrics and ⋮ missing).
- A visible tooltip adds about 5–8% of a core of CPU.
- Queue row ⋮ menu in split view is unreliable (appears late; items ignore input until Esc).
- Windows media keys / SMTC overlay are not supported (pre-existing; opt-in global hotkeys work).

Build note: `verifyDesktopReleaseJdk` rejects Temurin 21.0.13+9; the package was built
with Corretto 21.0.13.1.2. After switching JDKs, `createRuntimeImage` needs `--rerun`
(`verifyDesktopReleaseRuntime` correctly caught the stale runtime).

## Hands-on acceptance: Linux (WSL)

Pass: browse, artwork shapes, playback controls, MPRIS controls, settings persistence.
Not checked: gapless, settings export/import.

Fail or bugs:
- Release zip has no executable bits (blocker 3).
- First launch hangs before any window when `secret-tool` needs to prompt; the keyring
  call runs on the UI thread with no timeout, and killing it shows a raw error and exits.
- MPRIS `artUrl` contains the Subsonic token and salt.
- Playback costs about 1.2 cores on WSL's software renderer; confirm on real GPU drivers.
- Elapsed time, waveform and title overlays can go blank in split view; confirm on a real
  GNOME/KDE session.
- Close hangs in `nativeFree` when the audio device stalls; playback failures show no error.
- Full player clipped at 1280×800 (as on Windows).
- `.desktop` lacks `StartupWMClass`; Library search field is not focused when opened.
